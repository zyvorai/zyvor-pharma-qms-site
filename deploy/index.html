Deploy

Five ways to run it.

Desktop launchers, Linux or Mac compose, macOS FluxVM, k3s/Helm, or Windows Docker Desktop / WSL: the same pilot stack of Postgres, a Go API and a web console. Pilot, not validated, not 21 CFR Part 11 / Annex 11, synthetic data only.

Desktop launcher

macOS app, Windows executable, or a command-line launcher: starts Postgres if needed, runs the API with the console on one local port, and opens your browser. Best for an afternoon try on your own machine.

Mac or Linux · Compose

Podman or Docker Compose: Postgres, API and UI. One command up. Also the path inside WSL2.

Mac · FluxVM

A contained plant-like stack in a macOS VM, with a helper script. Compose fallback if the VM control plane is offline.

Kubernetes · k3s

Helm chart and raw manifests for API, UI and Postgres. Build and import local images for air-gapped labs. Defaults to one API replica.

Windows

Docker Desktop compose script, or WSL2 running the Linux compose script.

Before anyone else can reach it

Turn on strict mode.

Shipped deployments start in dev mode

None of the shipped compose, k3s or desktop deployments enable strict authentication. In the default dev mode the server trusts identity headers and defaults to admin, so never expose a default deployment to anyone but yourself. For anything others can reach, set strict mode, mark the environment as production (the server then refuses to start unless strict), and set a one-time bootstrap password. Put it behind a proxy that overwrites forwarded-for headers and terminates TLS.

Other switches, at a high level

An allowed-origins list for a UI on another origin; a secret key if connectors store secrets; passkey, OIDC and SAML settings if you use them; an opt-in to let connectors reach private internal hosts (blocked by default); an AI mode switch (off disables the drafting assistants). Database credentials in the shipped files are demo values: change them.

Rollback of the newest migrations

29 forward migrations apply at start-up. Opt-in down scripts exist only for the newest three (site scoping and the workflow engine); older migrations are restored from backup. The rollback tool is a dry run unless confirmed, runs newest first, and the older application version must be deployed before restart. Back up the database first.

Honest caveats

Single node: the scheduler, connector worker and login throttle run inside one API process, and multi-replica operation is untested. Not production-hardened, not a validated GxP hosting claim. Backups, TLS and database privileges are yours.
