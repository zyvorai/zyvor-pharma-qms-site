IT and security questions

Straight answers for your team.

Where does data live?On infrastructure you operate — PostgreSQL behind the Go API. Desktop home under ~/.zyvor-pharma-qms for local binaries.
Cloud required?No. Compose, FluxVM, k3s, or native desktop. SaaS is not the default story.
SSO / MFA?In strict mode: OIDC (code + PKCE) and SAML 2.0 SSO (SAML is pilot), SCIM 2.0 provisioning (pilot), TOTP and passkeys (pilot). Roles stay local; SSO / SAML / SCIM cannot grant admin. The default dev mode and desktop role selector trust identity headers: synthetic walkthroughs on your own machine only.
Is traffic encrypted?You terminate TLS at your reverse proxy / ingress. Localhost desktop demos often use HTTP on loopback only.
Multi-site / tenant?Site scoping exists but is partial and has had no independent review. Not a multi-tenant SaaS control plane.

Backups?Your Postgres backup policy. The product does not ship a managed backup service.
Pen tested?No. An AI-assisted code review was done; it is not an independent audit or pen test.
Source code?Private product repository. Public site is marketing + install scripts only.
Part 11?No. Not validated. Customer owns validation if they move beyond synthetic pilots.
Dependencies?Go API, React console, PostgreSQL, optional Podman/Docker for local Postgres.
Windows?Yes: PharmaQMS.exe launcher, Docker Desktop compose script or WSL compose path (bundles on request).
macOS?Yes: PharmaQMS.app and CLI desktop launcher (bundles on request).
Updates?Via product releases you choose to deploy. The public installer scripts verify SHA-256 of a bundle, but no bundles are published yet; evaluation bundles are available on request. Migrations apply at start-up; opt-in down scripts exist only for the newest three.
Outbound calls?Connectors, webhooks and SSO metadata fetches use an SSRF address guard (private and internal targets refused unless the operator opts in). Connector secrets are encrypted or referenced by restricted environment names.
Exposure?Run strict mode behind a proxy that overwrites forwarded-for headers and terminates TLS. Shipped deployments start in dev mode; never expose them. Many write endpoints lack per-role checks. Single node only; multi-replica is untested.
Live demo?pharma.zyvor.dev: shared, read-only, synthetic data; may be reset. Not for real data.
Logging?API logs + hash-chained application audit events (verify endpoint). Wire to your SIEM as you prefer.

Still unsure? Email security@zyvor.dev or sales@zyvor.dev. Please do not file public GitHub issues with sensitive infrastructure detail.
