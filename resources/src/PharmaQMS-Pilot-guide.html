Before you start

  • Podman or Docker Desktop (for Postgres), or any Postgres on :5432.
  • Or ask us for an evaluation bundle or compose / k3s / FluxVM files. Keep a default instance on your own machine; use strict mode for anything shared.

What a pilot should prove

1. Health/healthz on the local address (port 8080) returns ok.
2. Catalogue/api/v1/features lists 84 entries (73 modules + 11 AI assistants), a maturity map of pilot / partial entries, and markets india / us / eu / global.
3. Batch pathAs mfg, create a batch; as lab, enter results; as qa, approve / release.
4. OOSTrigger an out-of-spec result and walk the OOS record.
5. Spine depthRun the guided eBMR in order with second-person verification, print the executed batch record PDF, close a CAPA with an effectiveness check.
6. MarketsDraft an APQR (India) or APR (US) / PQR (EU) stub; work the Revised Schedule M checklist as a self-assessment.
7. StopQuit the app or run installer down. Data stays under ~/.zyvor-pharma-qms / your Postgres.

Decision questions

Does the spine match your plant?

Batch → lab → QA without exporting to Excel mid-flight.

Can IT host it?

Compose, FluxVM, k3s or Windows/WSL — pick one path.

What must validation cover?

You own IQ/OQ/PQ. This product is not validated for you.

What integrations matter?

ERP / LIMS connectors are a generic HTTP framework (pilot), not vendor-certified adapters; plan certified integration as a phase-2 ask.

Not a regulated pilot by itself. Contact sales@zyvor.dev for a guided walkthrough. Product source is private; this public site ships no application code.
